# system.css — the roadmap

How the engine improves over time, written down once (2026-09-29, Mike:
"help me make a plan on how to improve system.css over time"). The
engine is one file with a fixed layer spine and a closed vocabulary; every
project on the stack pins a tag. That shape decides the process.

## The rules of change

1. **A specimen first.** A new engine word (a class, a knob, a recipe) is
   born in the lab (`site/lab/*.html`) before any product page wears it.
   The vocabulary guard fails on an engine class no specimen wears; the
   lab guard fails on a specimen that breaks the laws it teaches.
2. **A law is a test.** Every rule the skill states in prose earns a
   guard in `engine_test.go` or `cssaudit` the day it is decided. A rule
   without a test is a suggestion.
3. **Subtract before you add.** The engine's size is the enemy; a change
   that deletes a rule and its specimen is the best kind. A new class
   needs a written reason in the commit and a specimen; a new layer
   needs a conversation.
4. **The tag is the contract.** A project consumes a tag, never master.
   Patch (x.y.Z): a rule fixed, a specimen added, docs. Minor (x.Y):
   a word added or a recipe changed in a way a page can see. Major
   (X): a word removed, a knob renamed, the spine changed. The
   changelog is the tag message.
5. **The consumer decides the direction.** While EventOS is the only
   product, a gap found there is raised here and flows back through a
   tag; when the second project consumes the engine, both do. Neither
   edits its copy.
6. **Addition by deletion.** A release that removes more lines than it
   adds is celebrated in its tag message. Nothing in the process may
   charge a deletion.

## The loop, per change

    lab specimen → test (engine, lab, vocabulary, links) → commit → tag
    → in the project: go get, sync, look, commit

An engine edit while iterating on a product page: `go work init .
../system-css` there, edit the engine here, sync there, look; then the
loop above lands it. The workspace file never commits.

## Now → the next release (v0.4)

- [ ] **Advanced section** on the site: `.wash` (the page's tint, the
  isolation law, the hue-shifted second pool), `.stack` (one grid cell
  for overlays: a badge on a card, a legend over a chart, a caption on a
  frame, a skeleton under content), `.stack` + `.hud` + `.grid` + `.lcr`
  for complex screens made of primitives, `.canvas` regions, `.rise`.
  Each with a lab specimen.
- [ ] **Greenfield demos** — the four 2025 pages retired; new full pages
  generated by `cmd/demos` on the `charts` package (geometry in Go,
  paint by the engine): an operations dashboard, an analytics report, a
  field app on the phone shell, a landing page. Each sets its own hue,
  skin, corners and size at the root — the colour engine on display.
- [ ] **`charts`** — the general SVG builders as a Go package the stack
  shares (bars · dot plot · line+area · horizontal bars · sparkline ·
  the heatmap recipe), ported from EventOS's view layer, tested for the
  laws: currentColor only, `--fg` for weight, `--hue-shift` per series,
  foreignObject text, no hand fonts.
- [x] **The vocabulary guard** (v0.4.0): every class the engine defines is
  worn by a specimen, a demo, a rocket or the site; the exceptions list
  carries a reason each. ITS FIRST RUN FOUND 55 WORDS no specimen wears
  — the outline table, the command palette, the month calendar, the
  google-maps chrome, the schema map, the roster's lens strip, the
  global search, and a few small ones (kicker, hud-pop, stub-slot,
  heat-month, tab-toggles). Each is one of two things: a specimen owed
  (the roster, the calendar, the outline table are engine words worth
  teaching) or a move to EventOS's project layer (the google-maps chrome,
  the schema map, the palette's internals are product parts the engine
  should not carry). The list is the queue below.
- [ ] **Pay the vocabulary down**: specimens for the roster (the
  server-driven table: lens strip, bulk list, the scroll), the calendar,
  the outline table, the heatmap, the kicker, hud-pop, stub-slot,
  tab-toggles; move gmap-*, erd-* and the palette's p-* into the app's
  project layer (addition by deletion — the engine loses ~120 lines).
- [ ] **Skin personalities** page from the 2025 site, rebuilt: each skin
  in light and dark with the ramps, the type scale, the semantic locks,
  a form — and the corners apart from it.

## Next (v0.5 → v0.9)

- [ ] **Search** on the site: the command-palette rocket over a baked
  index of headings (`site/index.json` from sitegen) — no server.
- [ ] **The density tiers documented** (.small/.medium/.large as
  container tiers; the rail math) with a specimen that resizes.
- [ ] **Print**: the media layer's print rules demonstrated; a demo page
  printed to PDF as a check in CI.
- [ ] **The form canon as a guard**: a lab test that every `<label>` in a
  specimen reads span → small → control, and every field fills the
  width.
- [ ] **A size budget**: lines per layer measured in CI and charted on
  the site; the budget a rate for new words like EventOS's rate guard —
  a layer may grow only with its specimens.
- [ ] **cssaudit adopted by EventOS** (its ratchet test imports the
  library's counters; one implementation).
- [ ] **The skills as the site's source**: today the site splits each
  SKILL.md by heading; the reverse — the site's pages ARE the skill — is
  the cleaner shape once the how-tos stabilise.

## Later (v1.0)

- The vocabulary frozen: a list of every class, knob and stamp with its
  specimen, the API of the engine. Removal is a major version.
- The layer spine frozen as the extension contract: an app writes only
  in `project`; a theme only in `skin`.
- A second product consuming the engine, and the sync direction fixed
  for good: the library is the source, the products pin.
- The rockets' Pro dependency gone: Rocket is free since Datastar
  v1.0.4; the one remaining Pro attribute a rocket uses, if any, replaced.

## What is not planned

A component library (variants, sizes, colours as classes), a build step,
a JavaScript layout system, a second stylesheet a page must also load
(the highlight companion is the one exception, loaded only with its
script), and any rule that cannot be tested.
